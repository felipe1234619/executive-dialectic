# Authentication callback deployment gate

Status: CODE PREPARED, NOT DEPLOYED. No Auth settings changed.

## Design
- `auth/callback.html` is a dedicated PKCE callback page for an isolated HTTPS preview origin.
- It consumes a one-time authorization code, requests Supabase Auth session exchange and validates the identity using `getUser`; it **does not** grant JCE permissions.
- The prototype deliberately avoids persistent session storage and signs out locally. A production session architecture requires a separate threat review, session management, MFA and backend authorization.
- Error and fragment details are not displayed or logged. URL parameters are removed immediately.
- `auth/config.mjs` is intentionally absent. Copy `auth/config.example.mjs` and supply only a publishable key after review; never commit privileged credentials.
- External CDN import is provisional and requires dependency pinning, bundling, integrity review and CSP before an institutional preview.

## Required release order
1. Review authentication dependencies of The Executive Institute in the shared Supabase project.
2. Establish a private HTTPS preview hostname and test callback; do not publish the public website or merge to main.
3. Bundle reviewed pinned dependencies and configure a restrictive CSP. Do not rely on the provisional CDN import for release.
4. Configure **exact** callback URL in Supabase Auth Redirect URLs; do not replace shared Site URL with an unimplemented destination.
5. Initiate a fresh login link from a controlled sign-in flow with explicit `emailRedirectTo`; never reuse the expired invitation.
6. Complete real session/MFA tests, session revocation, and verified server-side identity lookup.
7. Validate active organization membership against current database state; test A/B isolation with two real test users and two test organizations.
8. Independently approve audited ADMIN bootstrap and JCE integration.
9. Only then authorize a controlled institutional preview.

## Explicit non-goals
- No automated creation of an Auth user (the verified founder already exists).
- No modifications to `auth.users`, JCE tables, service-role permissions or shared project URL settings.
- No deployment or invitation link generated by this branch.
